# INKAI — запуск: що зробити (по порядку)

> **Режим «тільки YYOKAI» (`solo:true` у `config.js`)**: без ФОП, без підписок майстрів, без вибору майстра й міст. Усі призи, знижки й розіграш — лише у тебе; кожен гравець автоматично «прикріплений» до тебе. Щоб потім повернути партнерів — постав `solo:false` (код майстрів і підписок збережено).

## 0. Що в папці
`game1.html` (гра) · `core.js audio.js social.js shop.js chests.js game.js meta.js duel.js slots.js legal.js` (код) · `config.js` (**усі ключі й реквізити тут**) · `sw.js` (кеш + push) ·
`privacy.html terms.html raffle-rules.html` (юридичні сторінки) · `hash.html` (хеш пароля адміна) · `bump.py` (зміна версії) ·
`firestore.rules` (правила бази) · `jobs.js` (фонові задачі: розіграш, нагадування) · `ECONOMY.md` · `ASSETS.md`.
Файл `firebase-messaging-sw.js` більше **не потрібен** — його замінив `sw.js`.

## 1. Хостинг
GitHub Pages (або будь-який HTTPS-хостинг). Усі файли — в одній папці, в корені сайту. Підключи свій домен і HTTPS. Service worker і вхід через Google/Apple працюють лише по HTTPS.

## 2. Firebase (безкоштовний тариф Spark вистачає на старт)
1. console.firebase.google.com → Create project → додай **Web app** → скопіюй `firebaseConfig` у `config.js → firebase`. Увімкни **Analytics** (потрібен `measurementId`).
2. **Authentication → Sign-in method:** увімкни **Google** і **Apple**. Authentication → Settings → **Authorized domains:** додай свій домен.
   Apple (можна пропустити на старті — тільки Google): потрібен Apple Developer-акаунт (Services ID, Key), у налаштуваннях вказуєш посилання на `privacy.html`.
   Google: у «OAuth consent screen» вкажи посилання на `privacy.html` і `terms.html`.
3. **Firestore Database → Create database** (production). Потім **Rules** → встав вміст `firestore.rules`, заміни `ADMIN_UID` на свій UID
   (зайди в гру через Google, Authentication → Users → скопіюй User UID) → Publish.
4. **Cloud Messaging → Web push certificates → Generate key pair** → `config.js → vapidKey`.
5. Пароль адміна: відкрий `hash.html` у браузері, введи пароль, скопіюй хеш у `config.js → adminHash`.
6. (Рекомендовано) Firestore → **TTL policy** для колекції `duels` по полю `created` (автоочищення старих дуелей).

## 3. Реквізити й юридичне (**обов'язково до запуску**)
1. У `config.js → org` впиши справжні: ПІБ (фізична особа, ФОП не потрібен), адресу (можна місто), e-mail, Telegram. Вони автоматично підставляться на всі юридичні сторінки.
2. У `config.js → prize` перевір: місто, суми (7000 / 1500 грн), `discountSlots` (10), `claimDays` (30) — вони мають збігатися з грою (`slots.js`: `SLOT_MAX`, `CLAIM_DAYS`).
3. **Покажи privacy / terms / raffle-rules юристу.** Це якісні шаблони, але не юридична консультація: оподаткування призів, умови рекламних акцій, дитячі дані та вимоги App Store/Google Play залежать від твоєї форми діяльності й країн аудиторії.
4. Після будь-якої зміни текстів збільш `legalVersion` у `config.js` — гравці побачать запит на згоду знову.

## 4. Профіль майстра YYOKAI і партнери
1. Увійди в гру → Профіль → адмін-панель (пароль з кроку 2.5) → **«Мій профіль YYOKAI (∞)»** — без цього призи й знижки не працюють.
2. Підписки й оплата майстрів у режимі `solo` вимкнені — посилання `pay` не потрібні.
3. Фото майстра (необов'язково): `img/masters/yyokai.jpg` або `org.photo` у `config.js`.

## 5. Фонові задачі (розіграш, нагадування, Telegram)
GitHub → Settings → Secrets → Actions: `FIREBASE_SA` (JSON сервісного акаунта: Firebase → Project settings → Service accounts → Generate key), `TG_TOKEN` (токен Telegram-бота від @BotFather).
Файл `jobs.js` у `scripts/`, workflow — `.github/workflows/` (як було). Розіграш відбувається в останній день місяця о 20:00 за Києвом, лише серед гравців 18+.

## 6. Ресурси (необов'язково — без них працюють емодзі та синтезована музика)
Дивись `ASSETS.md`: де лежать картинки, музика, звуки й як вони називаються.

## 7. Кожна наступна заливка
`python3 bump.py НОВА_ВЕРСІЯ` (напр. `20261101a`) → залий ВСІ файли. Телефони не візьмуть старий кеш, а якщо якийсь файл забули залити — внизу екрана з'явиться червона плашка з його назвою.

## 8. Перевірка перед рекламою (на 2 телефонах і в «чистому» браузері)
- [ ] Перший запуск: екран віку й згоди; 18+ → гра; «до 16» → лише гість, вхід заблоковано.
- [ ] Вхід Google **і** Apple; нік; навчальний раунд; перший сундук.
- [ ] Рейтинг: тиждень / місяць / міста / весь час; твоє місце видно на кожній вкладці.
- [ ] Дуель: створити → надіслати посилання → прийняти на другому телефоні → зіграти → результат, печатка.
- [ ] Заявка на знижку: умови → слот → заявка у Firestore (`claims`) → повідомлення майстру в Telegram. Після 10 заявок — повідомлення «слоти закінчились».
- [ ] Профіль → «Приватність і дані»: вивантаження JSON, видалення акаунта (потім перевір, що документів `users/…`, `public/…` нема).
- [ ] Повторний запуск без інтернету: сторінка відкривається з кешу.
- [ ] Правила Firestore: в консолі Rules Playground перевір створення заявки без слота (має бути заборонено) і 11-й слот (заборонено).

## 9. Що ще варто зробити перед великим трафіком
- Серверна перевірка результатів (Cloud Functions): зараз монети, дні, дуелі приймаються з пристрою; призи ти підтверджуєш вручну, тому для старту це прийнятно.
- Зібрати Tailwind у статичний CSS (прибере залежність від CDN на першому запуску). Повторні запуски вже швидкі завдяки кешу.
- Пройти по `ECONOMY.md → «Що стежити після запуску»` через тиждень.
